# The Stone Wardens — A Fallen Firmament

A password-protected campaign site for our D&D 5e (2024 rules) party, hosted on GitHub Pages:
**https://blobberus.github.io/Stone-Wardens/**

| Tab | What it does |
| --- | --- |
| **Map** | Interactive world map. Drop pins with a type (city, town, village, temple, danger, …or your own custom types), a title and a Markdown description. |
| **Characters** | Card grid of every character, expandable into full 2024 character sheets. Builder for any level with class, subclass, species, background, feats and spells. Level-up menus open the right slots. Inventory draws on every SRD weapon, armor and item, and you can add custom ones. |
| **Journal** | Obsidian-style notes bound like a book: chapters, a table of contents, backlinks, tags, callouts and `[[links]]` to anything on the site. |
| **Compendium** | The shared library: SRD 5.2 rules content plus everything the party has added (custom weapons, items, abilities, location types…). |
| **Warden's Library** | Reads campaign documents (PDF, Word `.docx`, Markdown, images) from the `wardens-library/` folder. |

## First-time setup (repo owner)

1. **Create a fine-grained token**: GitHub → Settings → Developer settings → *Fine-grained tokens* → Generate.
   - Repository access: *Only select repositories* → `Stone-Wardens`
   - Permissions → Repository → **Contents: Read and write** (nothing else)
2. Open **https://blobberus.github.io/Stone-Wardens/setup.html**, paste the token, choose the site password and press
   *Check token, encrypt & commit*. This writes `vault.json`, which holds the token encrypted with your password
   (PBKDF2-SHA256, 600k iterations, then AES-256-GCM). The password itself is never stored.
3. Wait about a minute for Pages to redeploy, then share the password with the party.

To change the password or replace an expired token, run setup again.

> **Security notes.** Anyone with the password can read and write campaign data. The repo is public, so the data
> files under `content/` can also be read on github.com. Choose a long passphrase, because `vault.json` is public and could
> be attacked offline.

## How saving works

- Every edit is stored on your device as soon as you make it, so a crash or closed tab loses nothing.
- **Save** (sidebar button or `Ctrl+S`) commits all your changes to the repo in one commit, and then everyone sees them.
  If you try to leave with unsaved work, the browser warns you first.
- Unsaved changes are also saved to the repo automatically, at most 10 minutes after you make them. Change the
  interval in **Settings** (0 turns it off), or tick "Also save shortly after each edit". With both off, the site
  reminds you to save every 10 minutes instead.
- The site checks for other players' changes every two minutes and whenever you return to the tab.
  If two people edit the same thing, you'll be asked which version to keep.

## Link syntax (works in every description and note)

| Write | Links to |
| --- | --- |
| `[[Session 3]]`, `[[Session 3#The Ambush]]`, `[[Session 3\|alias]]` | a journal note, a heading in it, or the note shown under another name |
| `[[map:Old Mill]]` | a map location |
| `[[char:Thorin]]`, `[[char:Thorin#hp]]` | a character, or a section or stat on their sheet |
| `[[weapon:Longsword]]` `[[spell:Fireball]]` `[[item:…]]` `[[feat:…]]` `[[ability:…]]` `[[species:…]]` `[[class:…]]` | compendium entries |
| `[[doc:Player Primer]]` | a document in the Warden's Library |
| `![[Session 3]]`, `![[map.png]]` | embeds a note or an image inline |

Obsidian formatting also works: `==highlight==`, `%%hidden comment%%`, `#tags`, `- [ ] tasks`, tables, and callouts
(`> [!warning] Title`, foldable with `> [!tip]-`).

## Repository layout

```
index.html, setup.html     the site (no build step: plain HTML/CSS/JS modules)
assets/                    styles, icons, scripts (assets/js/core = shared, assets/js/views/<tab>)
srd/                       SRD 5.2 rules data (generated by tools/build_srd.py) + stubs/
content/                   campaign data written by the site (characters, locations, journal, library)
wardens-library/           documents for the Warden's Library tab
vault.json                 encrypted access token (created by setup.html)
```

Run locally with `python -m http.server` in the repo root and open `http://localhost:8000/?sandbox`.
Sandbox mode keeps everything in your browser.
